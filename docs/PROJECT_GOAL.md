# AGORA 股票量化工作台 · 项目目标

> 一句话版本：一个住在自己电脑上的 A 股短线量化工作台——收盘后自动把当天该做的事做完，用「波浪周期 + 情绪 + 量价」方法论和多个 AI 分析师协作研判，把所有结论讲清楚依据，把算不出的东西明说算不出。

## 一、项目愿景

打造一个**个人可长期使用的 A 股量化研究 + 短线研判闭环**：从数据入库、选股扫描、收盘复盘、舆情采集、收益验证、回测与因子体检，到「多 agent 短线研判」——全部在一个本地工作台内完成，不需要手工整理数据，也不依赖任何"看起来有道理"的编造结论。

## 二、目标用户与使用场景

- **用户**：本人（个人 A 股短线与量化研究者），单机使用。
- **日常场景**：打开工作台，在选股台候选池里挑股票、一键加入自选；点「AI 研判」让多个 AI 分析师协作，从候选池里筛出短线最有潜力的几只；在自选页集中盯自选行情；在情绪页看行业资金流向；收盘后回来看自动任务链的结果与复盘；隔几天回来看收益回填，想验证策略时跑回测和因子体检。

## 三、核心目标

1. **一条命令启动，一处打开全部**：`serve.py` 一个进程同时提供接口和 14 个页面（总览、选股台、情绪、流程、因子、台账、行情 K 线、舆情、AI 复盘、回测、自选、AI Agent、设置、Agent 报告），所有页面数据来自真实数据库实时查询。
2. **收盘后一键完成九步任务链**：`preflight` → `calendar` → `market_data` → `backfill_returns` → `integrity` → `scan` → `collect_news` → `agents` → `persist_experiment`。严格串行、可重复执行；失败步骤显式暴露且不提交成功实验结果。
3. **每个结论都可追溯**：复盘结论分三级标注（事实 / 规则计算结果 / 待验证判断），Agent 公开消息按角色交接并以 `agent_events` 序号持久化，舆情条目保留来源、发布时间与原始链接，AI 只允许基于已存证据回答且必须带引用。
4. **算不出的东西明说**：缺数据、未配置、样本不足、模型不达标、未来未到、未成交，一律以明确的缺失状态和原因呈现，绝不补零、绝不编造、绝不静默降级。
5. **用真实数据验证自己**：独立 `experiment_returns` 按 `t1_close`、`t2_open`…`t10_open` 验证收益，成交与收益只有这一份口径（实验台账不再存 `entry_*` / `ret*` 列）；滚动回测使用另一条链路上明确标注的 `picks.ret1/ret3/ret5/ret10` 字段；因子机器学习体检提供样本外 IC / AUC / 分桶单调性。
6. **多 agent 短线研判（短线操作口径）**：
   - 用自己的波浪周期情绪理论方法论（stock-cycle-wave-macd-volume skill）从候选池先做粗筛，**候选数量面板可改**（默认 200，上限 200）。
   - 两级混合编排：粗筛打分 → 对前 N 只做深度分析（方法论分析师 40% + 舆情分析师 30% + 走势分析师 30%）→ 最终 M 只做多方/空方陈述 + 公开反驳 + 风控，输出短线潜力排名。深度分析与最终数量同样**面板可改**（默认 8 / 3，上限 30 / 10）。
   - 研判输入全部来自已入库数据（行情、K 线技术指标、资金流、TrendRadar 舆情）；舆情只做相关性/时效/来源可信度过滤与评估。
   - 模型走 **OpenAI 兼容接口**；base URL 为 `https://grok.xuan.christmas/v1`，默认模型 `grok-4.5`，凭据从 Git 忽略的 `workbench/.env` 加载到 `WORKBENCH_AI_API_KEY`。
   - 结果落库（`agent_runs` / `agent_judgments` / `agent_events`），可查进度、可追溯依据、可一键加入自选。
7. **参考项目**：调研 hsliuping/TradingAgents-CN（TradingAgents 中文增强版），只借鉴其**多源舆情评估 + 分析师/辩论/风控协作**的编排思路；不引入 LangGraph 依赖，不照搬其长线基本面口径——提示词按短线操作重写，方法论沿用我们自己验证过的波浪周期 + MACD + 量价体系。

## 四、范围边界

**在范围内**

- A 股行情、资金流、交易日历、基础信息入库与更新。
- 候选池筛选、因子计算、综合打分、资金确认与选股台账。
- 收盘后自动任务链与任务状态持久化。
- 舆情采集（合规核验过的来源，当前为 TrendRadar 热榜）、去重、股票行业关联、情绪分析、行业板块分组。
- 三级标注复盘与 AI 叙述（OpenAI 兼容接口，真实凭据就绪后才启用）。
- K 线指标、全市场筛选、回测、因子/模型体检与页面展示。
- 自选股管理（独立自选页 + 选股台/行情页自选面板）与行业资金流向。
- 多 agent 短线研判（面板参数可调、进度可查、结果落库、一键加自选）。

**不在范围内**

- 实盘下单与自动交易。
- 用户系统、云部署与多用户权限（本机单用户，接口默认只监听本机）。
- 未完成合规核验的数据源。
- 未经真实数据验证的 AI 摘要或模型预测当作交易信号。
- 照搬 TradingAgents-CN 的全量多 agent 框架与长线基本面分析口径。

## 六、成功标准

- 页面上的每个数字都能追溯到数据库里的真实记录。
- `agent_events` 事件序号单调递增；SSE 先重放历史事件，再按 `after_seq` 续接实时事件。
- `experiment_returns` 区分 `available`、`status/reason`、真实 0 与组合现金槽位 0；任何不可用 horizon 不显示为 0.00%。
- AI 未配置时，研判按钮禁用、接口明确返回 503 + 缺什么，绝不编造结论。
- 研判参数（候选/深度/最终）面板可改且后端按上限钳制，防止超长任务打爆模型。
- 回测与模型体检结果如实展示，包括「当前没有可测期数」和「因子无区分度、门槛拒绝」这类负面结论。

## 七、项目原则

- **数据真实优先**：宁缺毋假，缺失就是缺失。
- **失败显式暴露**：不吞异常、不兜底、不伪装成功。
- **可重复可追溯**：所有写入幂等，所有结论带依据。
- **本地优先**：数据留在本机，服务只监听本机，凭据保存在 Git 忽略的本地 `.env`，不进入仓库。
- **借鉴不照搬**：外部项目只吸收思路与结构，口径按自己的短线目标重写。
- **不为了好看而失真**：口径取舍写进结果（如回测覆盖率、过拟合缺口），用户永远看得到代价。
