# Hermes 股票量化工作台 API 与五页动态化设计

## 1. 目标

将现有“Python 扫描引擎 + DuckDB 数据库 + 五个静态 HTML 页面”改造成一个本地可运行的完整工作台。

完成后，用户通过一个本地地址完成以下操作：

- 查看数据更新时间和最近一次扫描结果。
- 启动新的在线或离线扫描。
- 查看候选股票、入选原因和淘汰原因。
- 查看股票的结构、MACD、成交量、资金和行业因子。
- 查看市场与行业情绪。
- 查看历史选股、后续收益和策略表现。

## 2. 核心原则

### 2.1 数据职责

- Tushare 是上游数据供应商，负责提供行情、交易日历、资金流和基础信息。
- DuckDB 是工作台的统一本地数据仓库，保存经过入库的数据和扫描结果。
- FastAPI 只通过数据访问层读取 DuckDB，不允许页面直接调用 Tushare。
- 在线扫描时，由扫描引擎调用 Tushare 更新数据，再写入 DuckDB。
- 页面只展示真实数据、明确的空状态或“待接入”，不使用无标注的模拟数字。

### 2.2 失败处理

- 数据库不存在、表缺失、扫描失败和配置错误直接返回明确错误。
- 不使用静态 JSON、旧扫描结果或模拟数据自动掩盖错误。
- 页面显示错误原因和可执行动作，例如“尚未入库，请先运行在线扫描”。

### 2.3 范围控制

- 保留现有五页的信息架构，但删除重复说明和装饰性内容。
- 不引入 Vue、React 等前端框架。
- 不在本阶段训练机器学习或深度学习模型。
- 不在本阶段实现用户系统、云部署和多用户权限。

## 3. 总体架构

```text
Tushare
  ↓ 在线更新
engine/ingest_tushare.py
  ↓
DuckDB market.duckdb
  ↓
app/repositories + app/services
  ↓
FastAPI REST API
  ↓
原生 JavaScript 页面控制器
  ↓
五个 HTML 页面
```

FastAPI 同时提供 API 和静态页面。用户启动服务后访问根地址，不再直接双击 HTML 文件。

## 4. 后端模块

新增 `workbench/app/`：

- `main.py`：创建 FastAPI 应用、挂载静态页面、注册路由。
- `config.py`：读取应用配置并解析绝对路径。
- `dependencies.py`：提供数据库连接和服务依赖。
- `errors.py`：统一业务错误和 HTTP 错误格式。
- `schemas/`：定义接口输入输出结构。
- `repositories/`：只负责 DuckDB 查询，不包含页面逻辑。
- `services/overview.py`：汇总首页和数据新鲜度。
- `services/stocks.py`：候选股票、详情、归因和筛选。
- `services/sentiment.py`：市场、行业和资金共振数据。
- `services/factors.py`：因子值、贡献、权重和分布。
- `services/ledger.py`：历史选股、收益和策略统计。
- `services/scans.py`：启动扫描、记录状态和返回结果。
- `api/`：按业务域定义 FastAPI 路由。

现有 `engine/` 保持量化计算职责，不引入 HTTP 或页面代码。

## 5. API 设计

所有接口统一使用 `/api` 前缀。

### 5.1 系统与总览

#### `GET /api/health`

返回服务状态、数据库是否可读和当前版本。

#### `GET /api/overview`

返回：

- 最新已确认交易日。
- 各核心数据表的最新日期和行数。
- 最近一次扫描的策略、时间、候选数、通过数和入选数。
- 当前扫描任务状态。
- 首页入选股票摘要。

### 5.2 扫描任务

#### `POST /api/scans`

请求字段：

- `strategy`：策略名，默认 `strong_mainup`。
- `online`：是否通过 Tushare 更新数据。
- `record`：是否写入选股台账。

返回 `202 Accepted` 和任务编号。扫描在后台线程执行，避免浏览器请求长时间阻塞。

同一时间只允许一个扫描任务。已有任务运行时再次请求返回 `409 Conflict`。

#### `GET /api/scans/{job_id}`

返回：

- `queued`、`running`、`succeeded` 或 `failed`。
- 开始时间、结束时间和错误信息。
- 成功后的扫描摘要和入选股票。

任务状态保存在当前服务进程中。服务重启后未完成任务作废，已经写入 DuckDB 的扫描结果不受影响。

### 5.3 股票列表与详情

#### `GET /api/stocks`

支持：

- 扫描日期和策略。
- 是否通过门槛。
- 行业、资金确认类别和股票代码搜索。
- 综合分、因子分和行业热度排序。
- 分页。

#### `GET /api/stocks/{ts_code}`

返回：

- 股票基础信息和当前价格。
- 周线、日线结构结论。
- MACD、成交量、动量、题材、行业和资金因子。
- 每个因子的原始值、归一化值、权重和贡献。
- 综合得分、门槛结果、入选或淘汰原因。
- 最近行情与资金流序列。

### 5.4 情绪与行业

#### `GET /api/sentiment`

返回：

- 当前可计算的市场状态指标。
- 行业热度排行。
- 行业资金共振情况。
- 数据不足的情绪指标及缺失原因。

尚未实现的实时舆情和社区情绪字段返回明确的 `availability: pending`，不返回模拟分数。

### 5.5 因子实验室

#### `GET /api/factors`

返回策略权重、因子覆盖率、缺失率和候选池分布。

#### `GET /api/factors/{ts_code}`

返回单只股票的因子贡献、门槛结果和原始特征。

机器学习字段只返回训练状态。没有可验证模型文件时不返回预测概率和 SHAP 数值。

### 5.6 选股台账

#### `GET /api/ledger`

支持日期、策略、股票代码和收益状态筛选，返回分页台账。

#### `GET /api/ledger/summary`

返回：

- 入选数量。
- 已回填数量。
- T+5 和 T+10 平均收益。
- 正收益比例。
- 最大收益和最大回撤样本。
- 按策略和月份分组的表现。

样本不足时直接返回样本数和空统计，不计算误导性的比例。

## 6. 前端公共层

新增公共文件：

- `assets/css/theme.css`：颜色、字体、间距、表格和状态组件。
- `assets/js/api.js`：统一请求、超时和错误解析。
- `assets/js/app-shell.js`：导航、数据更新时间和扫描状态。
- `assets/js/format.js`：价格、收益率、金额和日期格式化。
- `assets/js/pages/`：五个页面各自的控制器。

页面必须具备：

- 加载状态。
- 无数据状态。
- 明确错误状态。
- 数据更新时间。
- 可重复请求的刷新按钮。

不保留静态 JSON 作为运行时备用数据。

## 7. 五页内容设计

### 7.1 选股台 `p1_desk.html`

保留：

- 最新交易日、数据更新时间和扫描状态。
- 在线扫描与离线扫描按钮。
- 入选股票列表。

- 股票详情抽屉或右侧详情区域。

- 重复的数据真实性说明。
- 纯装饰行情数字。

- 没有交互作用的示例股票行。

### 7.2 情绪页 `p2_sentiment.html`

保留：

- 市场阶段摘要。
- 行业热度排行。
- 行业资金共振。
- 当前入选股票与行业状态的关系。
- 待接入舆情模块的简洁占位状态。

删除：

- 多组重复排行榜。
- 无数据来源的情绪仪表盘。
- 长篇教学说明和重复脚注。
- 模拟社区帖子和模拟热度。

### 7.3 选股流程页 `p3_foundry.html`

保留：

- 当前策略门槛和行业去重结果。

删除：

- 重复展示同一批统计数字的卡片。
- 无法下钻的装饰流程节点。
- 大段流程解释。

### 7.4 因子实验室 `p4_factorlab.html`

保留：

- 策略权重。

- 单只股票因子贡献。
- 原始值、归一化值和贡献值对照。
- 机器学习训练状态。

删除：

- 未训练模型的模拟预测值。
- 模拟 SHAP 图。
- 重复的因子说明和装饰图表。

### 7.5 台账页 `p5_ledger.html`

保留：

- 历史选股表格。
- 日期、策略、股票和收益状态筛选。
- T+5、T+10 收益。
- 策略表现摘要。
- 尚未回填收益的清晰状态。

删除：

- 示例台账行。
- 重复的指标定义。
- 样本不足时的虚假统计图。

## 8. 视觉规范

### 8.1 颜色比例

- 约 75%：黑、白、深蓝灰。
- 约 15%：边框灰、次级文字和弱背景。
- 不超过 10%：状态和交互颜色。

### 8.2 基础色

```css
--bg: #070b12;
--surface: #0d1420;
--surface-raised: #121c2b;
--navy: #16243a;
--line: #263449;
--text: #f4f7fb;
--text-muted: #8d9aab;
--accent: #5f8fc9;
--positive: #3da678;
--negative: #c85d67;
--warning: #c49a4a;
```

### 8.3 使用规则

- 深蓝只用于导航、选中状态和重要交互。
- 绿色和红色只用于收益、趋势和风险。
- 黄色只用于数据缺失、待接入和警告。
- 删除大面积青色、紫色、渐变和发光效果。
- 同一屏幕最多出现一个主要强调色。
- 页面减少圆角和阴影，以边框、留白和字号建立层级。
- 表格和数字优先于装饰图形。

## 9. 测试策略

### 9.1 后端

- 数据库缺失和表缺失错误。
- 总览接口返回真实最新日期。
- 股票筛选、排序和分页。
- 股票详情因子映射。
- 台账空样本和已回填样本统计。
- 同时启动扫描时返回冲突。
- 离线扫描成功与失败状态。
- API 不访问未来日期数据。

### 9.2 前端

- 五页都能处理加载、成功、空数据和错误状态。
- 页面不再显示静态示例股票或模拟指标。
- 导航和查询参数在页面跳转后保持一致。
- 扫描完成后首页、流程页和台账页可以刷新。
- 颜色使用符合主题变量，不残留旧的大面积彩色样式。

### 9.3 验收

- 启动一个命令即可打开工作台。
- 五个页面均从 API 获取数据。
- 断开数据库后页面明确报错，不显示旧数据。
- 在线扫描经 Tushare 更新后，页面展示 DuckDB 中的新结果。
- 五个页面在常用桌面宽度下无明显溢出和遮挡。

## 10. 文档与运行方式

实现完成后更新：

```text
http://127.0.0.1:8765/
```

## 11. 完成标准

- FastAPI 服务、五页静态资源和 DuckDB 查询形成完整闭环。
- 五个页面全部动态化，不再把写死数字当真实结果。
- 页面信息量明显减少，核心操作和结论优先。
- 黑、白、深蓝成为绝对主色，其余颜色只承担状态含义。
- 在线扫描继续使用 Tushare，页面查询统一通过 DuckDB。
- 后端自动测试通过，五页完成浏览器验收。
