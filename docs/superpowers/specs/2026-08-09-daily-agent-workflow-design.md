# 每日选股工作流、Agent 通话与收益看板设计

## 目标

把当前分散的扫描、Agent 研判、实验落库和收益回填收束为一条每天可重复运行的严格工作流；让 Agent 之间通过可审计的公开消息交接观点；新增从次日开盘买入到 T+10 开盘卖出的收益计算；通过 SSE 实时展示辩论过程，并提供独立的历史研判报告看板。

## 已确认的产品口径

### 每日一键工作流

主入口使用现有 `PipelineManager → OneClickRunner`，固定顺序如下：

1. `preflight`：加载配置、校验策略、Agent、数据库和外部数据依赖。
2. `calendar`：确认目标交易日和数据截止日。
3. `market_data`：更新或准备行情、交易日历、资金流和候选所需历史。
4. `backfill_returns`：补算此前已产生的实验批次收益；当前批次尚未产生买入日，不在此步计算。
5. `integrity`：冻结输入并检查行情、指标、资金流和历史覆盖完整性。
6. `scan`：执行固定规则选股，冻结候选池、候选池哈希和策略版本。
7. `collect_news`：采集并关联舆情；来源不可用时明确失败。
8. `agents`：粗筛、三位分析师、公开多空辩论、风控定稿。
9. `persist_experiment`：在一个事务中保存任务成功状态、扫描台账、四组实验和 Agent 报告索引。

关键步骤严格串行。Agent 或舆情失败时，任务落 `failed`，不把规则结果伪装成完整成功批次，不写入成功实验结论。重跑沿用 `TaskTracker` 的业务幂等键和 `force` 机制。

### Agent 通话

采用编排器转发消息，不引入 LangGraph 或其他工作流框架。Agent 不共享隐藏思维链，只共享结构化的公开发言和数据引用。

固定角色和轮次：

1. `methodology`、`sentiment`、`trend` 三位分析师分别独立发言。
2. `bull` 多方读取三位分析师发言，提交多方开场。
3. `bear` 空方读取三位分析师发言和多方开场，提交反驳。
4. `bull_counter` 多方读取空方反驳，提交回应。
5. `risk_chair` 中性风控读取完整公开记录，提交最终判定、风险和行动建议。

每次发言都产生一个可审计事件：角色、股票、阶段、轮次、顺序号、内容、引用字段、时间和状态。模型必须输出结构化 JSON；解析失败整批失败，不用默认分数或文本兜底。

### SSE

SSE 只传输公开事件，不传输隐藏推理。事件类型固定为：

- `run.started`
- `stage.started`
- `message.delta`
- `message.completed`
- `stage.completed`
- `run.completed`
- `run.failed`
- `heartbeat`

`message.delta` 只在模型支持 OpenAI 兼容流式响应时产生；后端同时累积完整内容，`message.completed` 后再做 JSON 校验和落库。客户端断线可以从 `last_event_id` 或 `after_seq` 继续读取已落库事件。

### 收益计算

对每个成功选股批次的每个实验组，采用等权资金槽位：

- 信号日为 `T`。
- 第一个开市日 `T+1` 以 `open` 买入。
- `T+1` 以当日 `close` 卖出，记为 `T+1_close` 日内收益。
- `T+2` 至 `T+10` 分别以对应交易日 `open` 卖出，记为 `T+2_open` … `T+10_open`。
- 毛收益公式为 `sell_price / entry_price - 1`。
- v1 不扣手续费、印花税和滑点；接口显式返回 `gross` 和成本假设。
- 单票状态不补零：未成交、未来未到、目标行情缺失分别保留状态和原因。
- 未成交但资金仍在现金中的槽位对组合总收益贡献 0，这是现金收益口径，不把单票收益字段写成 0。
- 目标行情缺失时组合该期限不可用，返回 `available=false` 和覆盖统计。

汇总结果包含：计划股票数、已成交数、未成交数、可计算股票数、组合毛收益、收益平均值、收益中位数、覆盖率和每只股票明细。默认按 `rule / ai / hybrid / benchmark` 分组。

现有 `ret1 / ret3 / ret5 / ret10` 是旧的收盘收益字段。为避免改变历史字段含义，实施时新增独立 `experiment_returns` 表保存新口径；旧字段保留只读并标注 legacy，不再扩展为新含义。新表按 `run_id / group_name / ts_code / horizon` 存储 `t1_close`、`t2_open` … `t10_open`，接口只读取新表。

### 可视化报告

新增独立页面 `p13_agent_dashboard.html`，分为四个区域：

1. 批次选择和状态：交易日、策略、模型、输入数据截止时间、当前阶段、失败原因。
2. Agent 通话时间线：按股票和轮次展示分析师、双方和风控的公开发言，支持实时 SSE 追加。
3. 结论矩阵：三位分析师分数、双方核心观点、风控结论、风险、数据引用。
4. 收益验证：T+1 收盘、T+2 至 T+10 开盘的逐组收益卡片、覆盖率和股票明细。

报告由结构化事件和真实行情计算生成，不再额外调用模型写无法追溯的长摘要。页面支持实时批次和历史批次；历史批次没有实时流时直接读取已落库事件。

## 技术边界

- 保留 `OneClickRunner`、`TaskTracker`、`AgentJudgeManager`、`engine.agents` 和现有 API 兼容入口。
- 新增事件存储和收益字段时使用启动迁移，不修改真实数据库中的历史含义；旧收益字段迁移前先保留原值并写入明确的来源版本。
- SSE 使用 FastAPI `StreamingResponse`，事件源来自同进程事件总线加 DuckDB 已落库事件；服务重启后历史事件仍可查询。
- OpenAI 兼容客户端新增流式读取能力；非辩论阶段可以使用完整响应，辩论阶段必须使用流式事件协议。
- 前端继续使用原生 JavaScript、现有主题令牌和本地 ECharts，不引入前端框架或 CDN。
- 所有接口错误使用现有 `WorkbenchError` 信封；AI 未配置、模型请求失败、流式解析失败必须区分。

## 已确认的大模型接入

- OpenAI 兼容接口 `base_url` 使用 `https://grok.xuan.christmas/v1`，代码统一补齐 `/chat/completions`。
- API 密钥保存在 Git 忽略的 `workbench/.env`，启动时加载到 `WORKBENCH_AI_API_KEY`；不写入仓库、YAML、日志、数据库或 SSE 事件。
- `model` 继续由 `config/settings.local.yaml` 或设置页配置，不在代码中硬编码；启动状态接口显示 provider、base_url、model 和密钥环境变量是否已检测到，但不返回密钥值。
- 正式请求前用脱敏配置做连通性/协议检查；HTTP、TLS、鉴权、模型返回格式错误分别落为可区分的失败原因。

## 验收标准

- 同一个交易日和策略点击一次只产生一个运行批次；重复点击返回已完成批次或明确冲突。
- 任意关键步骤失败后，任务状态为 `failed`，失败步骤、错误和已完成步骤可查询，成功实验不会出现。
- Agent 事件顺序可重放；空方输入中包含三位分析师和多方公开发言；风控输入中包含完整公开辩论。
- SSE 客户端能收到阶段、消息增量、完成和失败事件；断线后可以按序号续传。
- 收益结果同时覆盖 T+1 收盘和 T+2 至 T+10 开盘；停牌、未成交、缺数据均不被当作真实 0。
- 选股工作流页、AI Agent 页和新增报告看板的状态、发言和收益口径一致。
- 现有测试保持通过；新增领域、API、SSE、数据库迁移、收益口径和页面契约测试。
