# 三步量化工作台设计

## 目标

把工作台收敛为可顺着操作的六页主流程：方法论选股、板块舆情、多 Agent 辩论、自选与行情、设置，以及总览。选股和舆情按钮必须在后台任务运行期间显示真实状态、阶段进度和日志；Agent 复用已有公开事件流。

## 用户流程

```text
总览 → 方法论选股 → 板块舆情 → 多 Agent 辩论 → 自选与行情
```

当前批次通过 `hermes.work-context` 传递 `run_id`、`as_of`、`strategy`、`data_cutoff` 和候选股票上下文。页面不得默默切换到另一批次。

## 页面边界

- 总览：当前批次、三步状态、最近任务和入口。
- 方法论选股：离线/在线扫描、扫描任务反馈、候选池、交接舆情。
- 板块舆情：当前批次行业聚合、新闻明细、采集任务反馈、交接 Agent。
- 多 Agent 辩论：候选池、公开分析/辩论事件、最终结果。
- 自选与行情：自选管理、搜索、K 线和技术指标，复用现有接口。
- 设置：AI 和舆情配置，密钥仍只从环境变量读取。

因子、台账、回测、AI 复盘和详细九步流程暂不放在主导航，不删除已有页面和接口。

## 任务反馈契约

扫描和舆情继续使用 `task_runs`，任务详情通过既有 GET 接口读取。运行中的 `result` 至少包含：

```json
{
  "progress": {
    "stage": "candidate_pool",
    "step": 4,
    "total": 7,
    "percent": 57,
    "message": "初步候选 259 只",
    "logs": [{"at": "...", "level": "info", "message": "..."}]
  },
  "steps": [{"name": "candidate_pool", "status": "running", "detail": "..."}]
}
```

阶段只报告后端真实完成的状态；不能用前端定时器伪造百分比。页面刷新后从任务详情恢复。

扫描阶段：`preflight`、`calendar`、`market_data`、`candidate_pool`、`factors`、`score`、`persist`。

舆情阶段：`config`、`resolve_trade_date`、`fetch_sources`、`deduplicate`、`link_industries`、`link_stocks`、`persist`。无法精确知道条数时只更新阶段文字，不捏造数量。

Agent 继续使用 `/api/agents/jobs/{job_id}/stream` 的 SSE 公开事件，缺失事件仍显示缺失，不补占位结论。

## 错误和幂等

- 真实后端错误原样显示脱敏后的错误信息。
- 已完成任务复用时显示“命中已完成批次”，不伪装成新任务。
- 任务失败后按钮恢复可用，保留失败阶段和日志。
- 刷新页面不会重新提交任务。

## 验收

1. 点击选股按钮后立即禁用并显示任务编号、进度条、阶段和日志。
2. 扫描完成后显示真实候选统计，并可把当前批次交给舆情页。
3. 点击舆情采集后立即显示任务编号、进度条、阶段和日志。
4. 舆情完成后保留新增、去重、关联等真实摘要。
5. Agent 页面接收同一批次并显示公开实时辩论。
6. 最终结果可加入自选并打开行情/K 线。
7. 设置页保存成功/失败状态明确。
8. 浏览器点击验收通过；针对性 Python 测试通过。
